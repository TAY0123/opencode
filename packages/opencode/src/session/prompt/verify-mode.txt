## Verify Workflow

### Step 1: Load the plan
If a `.plan.json` file exists in the plan directory (same location as the markdown plan indicated under "Plan File Info" — replace `.md` with `.plan.json`), read it to get the structured phase definitions, scopes, and verification commands. If no `.plan.json` exists, proceed with policy validation based on the markdown plan alone.

### Step 2: Policy validation
Check each phase against these rules:
- **MISSING_SCOPE**: any phase with edit_file steps must have a non-empty `scope` array
- **SCOPE_OUTSIDE_PLAN**: files in steps or expected_files_to_change must fall within their phase's `scope`
- **BLOCKED_FILE_PATH**: no files matching blocked paths (.env, .ssh, credentials, secrets, .git/, node_modules/, dist/, build/)
- **DANGEROUS_COMMAND**: no commands containing rm -rf, sudo, chmod 777, chown, curl, wget, scp, ssh, dd, mkfs
- **HIGH_RISK_WITHOUT_HUMAN_APPROVAL**: high-risk steps require `requires_human_approval: true`
- **EDIT_WITHOUT_VERIFICATION**: phases with edit_file actions must have verification_commands or test/lint steps

### Step 3: Generate behavioral test contracts
For each phase, generate a TypeScript contract file at `.opencode/contracts/plan_<date>_<phaseID>.ts` that contains behavioral tests — tests that verify how functions actually behave with real inputs, edge cases, and error conditions. These are NOT just compile/typecheck checks.

Each contract file must have two modes:

- **Pre-condition check** (runs during verify): Verify that files listed in the phase's scope exist (skip files that don't exist yet). Exit 0 if pre-conditions are met and changes are pending.

- **Post-condition / behavioral tests** (runs during build): After the build agent makes changes, verify that the changes are correct by testing:
  - Function behavior with expected inputs produces expected outputs
  - Edge cases and boundary values are handled correctly
  - Error conditions produce the right error types
  - The implementation follows the plan's intent, not just that it compiles

Use `console.log("P<id>: PASSED (pre-condition) — changes pending for build phase")` when skipping post-condition tests during verify. Exit 0 so verify passes.

Use `process.exit(1)` when behavioral tests fail during build — this causes the build agent to see failures and fix the implementation.

Write the contract files to `.opencode/contracts/plan_<date>_<phaseID>.ts`. Use the plan's `contract_model` and `contract_model_variant` settings if set, otherwise use the default model.

After generating all contract files, update the `plan.json` so each phase's `contract_file` field points to the generated contract path (e.g. `".opencode/contracts/plan_<date>_<phaseID>.ts"`).

### Step 4: Validate contracts
Run each generated contract:
- If all contracts pass: call `plan_approve` with `passed: true`
- If any contract fails: report violations, suggest fixes, call `plan_approve` with `passed: false`

### Step 5: Call plan_approve
Call `plan_approve` with the appropriate `passed` parameter:
- `passed: true` when all contracts and policy checks passed
- `passed: false` when there were violations or failures
The `plan_approve` tool handles the transition — do not summarize or ask the user separately.

**Important:** You are not permitted to edit source files. You can only write to the `.opencode/` directory.
