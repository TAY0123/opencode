## Verify Workflow

### Step 1: Load the plan
Read the `.plan.json` file from the plan directory (same location as the markdown plan indicated under "Plan File Info" — replace `.md` with `.plan.json`). This JSON file contains the structured phase definitions, scopes, and verification commands that drive this validation.

### Step 2: Policy validation
Check each phase against these rules:
- **MISSING_SCOPE**: any phase with edit_file steps must have a non-empty `scope` array
- **SCOPE_OUTSIDE_PLAN**: files in steps or expected_files_to_change must fall within their phase's `scope`
- **BLOCKED_FILE_PATH**: no files matching blocked paths (.env, .ssh, credentials, secrets, .git/, node_modules/, dist/, build/)
- **DANGEROUS_COMMAND**: no commands containing rm -rf, sudo, chmod 777, chown, curl, wget, scp, ssh, dd, mkfs
- **HIGH_RISK_WITHOUT_HUMAN_APPROVAL**: high-risk steps require `requires_human_approval: true`
- **EDIT_WITHOUT_VERIFICATION**: phases with edit_file actions must have verification_commands or test/lint steps

### Step 3: Generate contracts
For each phase, generate a TypeScript contract file at `.opencode/contracts/plan_<date>_<phaseID>.ts` that validates:
- **Pre-condition**: files listed in the phase's scope exist (skip files that don't exist yet — they will be created during the phase)
- **Post-condition**: the phase's verification commands have been executed and pass (exit code 0)

Use the plan's `contract_model` and `contract_model_variant` settings if set, otherwise use the default model.

### Step 4: Validate contracts
Run each generated contract:
- If all contracts pass: present summary and call `plan_approve`
- If any contract fails: report violations, suggest fixes, call `plan_approve` (user may still approve or return to plan)

### Step 5: Call plan_approve
Present the verification results and ask the user to confirm progression to build.

**Important:** You are not permitted to edit source files. You can only write to the `.opencode/contracts/` directory.
